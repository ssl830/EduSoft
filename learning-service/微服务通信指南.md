# Learning Service 微服务通信指南

## 概述

本文档说明了 Learning Service 中微服务间通信的设计和使用方法。

## 微服务通信架构

### 1. Client文件的作用

Client文件是微服务间通信的核心组件，它们的作用包括：

- **服务抽象**：将复杂的HTTP调用封装成简单的方法调用
- **统一配置**：集中管理服务地址、超时、重试等配置
- **异常处理**：统一处理微服务调用中的各种异常情况
- **认证传递**：自动传递用户认证信息到其他微服务
- **负载均衡**：配合服务发现实现负载均衡（后续可扩展）

### 2. 当前实现的Client

#### UserClient
- **用途**：调用 user-service 的相关接口
- **主要方法**：
  - `getUserById(Long userId)` - 获取用户信息
  - `getUserDetail(Long userId)` - 获取用户详细信息
  - `userExists(Long userId)` - 验证用户是否存在
  - `getUsersByIds(String userIds)` - 批量获取用户信息

#### CourseClient
- **用途**：调用 course-service 的相关接口
- **主要方法**：
  - `getCourseById(Long courseId)` - 获取课程信息
  - `getClassById(Long classId)` - 获取班级信息
  - `getSectionById(Long sectionId)` - 获取章节信息
  - `canUserAccessCourse(Long userId, Long courseId)` - 验证用户课程访问权限
  - `isUserInClass(Long userId, Long classId)` - 验证用户班级成员资格

#### ContentClient
- **用途**：调用 content-service 的相关接口
- **主要方法**：
  - `getResourceById(Long resourceId)` - 获取资源信息
  - `getResourcesByCourseId(Long courseId)` - 获取课程下的所有资源
  - `updateResourceProgress(...)` - 更新学习进度
  - `canUserAccessResource(Long userId, Long resourceId)` - 验证资源访问权限

## 使用方法

### 1. 在Service中注入Client

```java
@Service
public class HomeworkService {
    
    @Autowired
    private UserClient userClient;
    
    @Autowired
    private CourseClient courseClient;
    
    public void submitHomework(Long userId, Long homeworkId) {
        // 验证用户存在
        if (!userClient.userExists(userId)) {
            throw new IllegalArgumentException("用户不存在");
        }
        
        // 获取作业信息
        Homework homework = homeworkRepository.findById(homeworkId);
        
        // 验证用户是否属于该班级
        if (!courseClient.isUserInClass(userId, homework.getClassId())) {
            throw new IllegalArgumentException("用户不属于该班级");
        }
        
        // 执行作业提交逻辑
        // ...
    }
}
```

### 2. 异常处理

所有Client调用都可能抛出 `ServiceCallException`，建议统一处理：

```java
try {
    Map<String, Object> user = userClient.getUserById(userId);
    // 处理成功结果
} catch (ServiceCallException ex) {
    if (ex.getStatusCode() == 404) {
        // 用户不存在
        return "用户不存在";
    } else {
        // 其他错误
        log.error("调用用户服务失败", ex);
        return "系统错误，请稍后重试";
    }
}
```

## 最佳实践

### 1. 错误处理
- 总是考虑网络异常、服务不可用等情况
- 对于非关键的服务调用，考虑降级处理
- 记录详细的错误日志便于排查问题

### 2. 性能优化
- 避免在循环中调用微服务接口
- 使用批量接口减少网络调用次数
- 考虑添加缓存减少重复调用

### 3. 安全性
- 认证信息会自动传递，无需手动处理
- 在调用前验证参数的合法性
- 对敏感操作添加额外的权限检查

### 4. 监控和日志
- 开启client包的debug日志监控调用情况
- 使用健康检查工具监控服务状态
- 记录重要的业务操作日志

## 健康检查

### Actuator 端点
每个微服务都已配置了 Spring Boot Actuator，提供标准的健康检查端点：

- User Service: `http://localhost:8081/actuator/health`
- Course Service: `http://localhost:8082/actuator/health`
- Content Service: `http://localhost:8083/actuator/health`
- Learning Service: `http://localhost:8084/actuator/health`

### 使用 ServiceHealthChecker

`ServiceHealthChecker` 提供了智能的健康检查机制：

1. **优先使用 Actuator 端点**：如果服务配置了 Actuator，会先尝试调用 `/actuator/health`
2. **回退到业务接口**：如果 Actuator 不可用，会使用业务接口进行检查
3. **智能错误判断**：能够区分服务不可用和业务逻辑错误（如404）

```java
@Autowired
private ServiceHealthChecker healthChecker;

public void checkServices() {
    // 检查所有服务
    Map<String, Boolean> healthStatus = healthChecker.checkAllServices();
    
    // 获取不健康的服务
    String[] unhealthyServices = healthChecker.getUnhealthyServices();
    
    // 检查单个服务
    boolean userServiceOK = healthChecker.checkUserService();
    boolean courseServiceOK = healthChecker.checkCourseService();
    boolean contentServiceOK = healthChecker.checkContentService();
    
    if (unhealthyServices.length > 0) {
        log.warn("以下服务不可用: {}", Arrays.toString(unhealthyServices));
    }
}
```

## 故障排查

### 常见问题

1. **连接超时**
   - 检查目标服务是否启动
   - 检查网络连接
   - 调整超时配置

2. **认证失败**
   - 检查token是否正确传递
   - 检查目标服务的认证配置

3. **404错误**
   - 检查API路径是否正确
   - 检查目标服务是否提供该接口

4. **500错误**
   - 查看目标服务的日志
   - 检查请求参数是否正确
