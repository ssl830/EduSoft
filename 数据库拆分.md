# 数据库拆分方案（更新版）

## 重要说明

**关于AI微服务的调整：**
我们调整了AI微服务的架构策略：
- 保留Python AI微服务作为核心AI处理引擎
- 将原本的Java AI后端代码分散到各个微服务中，主要集中在learning-service
- 各微服务通过CommonAIServiceClient调用learning-service，learning-service再调用Python AI微服务
- 避免了AI功能分裂成两个独立微服务的问题

从你们的数据库结构来看，主要包含以下表：

### 核心表分类：

1. 用户相关：user

2. 课程相关：course, class, courseclass, coursesection, classuser

3. 学习相关：homework, homeworksubmission, practice, practicequestion, submission, answer, question

4. 内容相关：file_node, teaching_resource, notification, discussion, discussionreply

5. AI相关（现在主要在learning-service）：ai_service_call_log, chat_session, chat_message, chat_memory_summary

6. 记录相关：learning_progress, progress, selfpractice, selfsubmission, selfanswer, wrongquestion, favoritequestion

7. 导入相关：import_record

8. 知识库：teacherknowledgebase：

## 微服务数据库拆分方案

### 1. 用户服务数据库 (user-service-db)

```sql
-- 用户服务数据库
CREATE DATABASE user_service_db;

-- 用户表
CREATE TABLE user (
  id bigint NOT NULL AUTO_INCREMENT,
  user_id varchar(15) NOT NULL,
  username varchar(50) NOT NULL,
  password_hash varchar(255) NOT NULL,
  role enum('student','teacher','tutor') NOT NULL,
  email varchar(100) DEFAULT NULL,
  created_at timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY user_id (user_id)
);

-- 用户权限表（扩展）
CREATE TABLE user_permission (
  id bigint NOT NULL AUTO_INCREMENT,
  user_id bigint NOT NULL,
  permission_name varchar(100) NOT NULL,
  created_at timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY user_id (user_id),
  CONSTRAINT user_permission_ibfk_1 FOREIGN KEY (user_id) REFERENCES user (id) ON DELETE CASCADE
);
```

## 数据迁移策略

### 1. 数据同步策略

由于微服务间存在数据依赖关系，需要实现以下同步策略：
```java
// 用户服务 - 用户数据同步
@Service
public class UserDataSyncService {
    
    @EventListener
    public void handleUserCreated(UserCreatedEvent event) {
        // 通知其他服务用户已创建
        eventBus.publish(new UserCreatedEvent(event.getUserId(), event.getUserData()));
    }
    
    @EventListener
    public void handleUserUpdated(UserUpdatedEvent event) {
        // 通知其他服务用户信息已更新
        eventBus.publish(new UserUpdatedEvent(event.getUserId(), event.getUserData()));
    }
}

// 课程服务 - 课程数据同步
@Service
public class CourseDataSyncService {
    
    @EventListener
    public void handleCourseCreated(CourseCreatedEvent event) {
        // 通知学习服务和内容服务课程已创建
        eventBus.publish(new CourseCreatedEvent(event.getCourseId(), event.getCourseData()));
    }
}
```
### 2. 分布式事务处理
```java
// 使用Saga模式处理跨服务事务
@Service
public class LearningSagaService {
    
    @Transactional
    public void createPracticeWithQuestions(CreatePracticeRequest request) {
        // 1. 创建练习
        Practice practice = practiceService.createPractice(request.getPracticeData());
        
        // 2. 创建题目
        List<Question> questions = questionService.createQuestions(request.getQuestions());
        
        // 3. 关联练习和题目
        practiceQuestionService.associateQuestions(practice.getId(), questions);
        
        // 4. 发送通知
        notificationService.sendPracticeNotification(practice);
    }
}
```

```java
// 使用事件溯源保证数据一致性
@Service
public class EventSourcingService {
    
    @EventListener
    public void handleUserEvent(UserEvent event) {
        // 记录事件到事件存储
        eventStore.save(event);
        
        // 更新本地缓存
        updateLocalCache(event);
    }
    
    @Scheduled(fixedRate = 60000) // 每分钟同步一次
    public void syncData() {
        // 从事件存储中获取未处理的事件
        List<Event> events = eventStore.getUnprocessedEvents();
        
        // 处理事件
        for (Event event : events) {
            processEvent(event);
        }
    }
}
```
